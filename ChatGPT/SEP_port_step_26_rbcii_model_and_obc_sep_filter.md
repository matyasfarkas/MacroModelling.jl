# SEP Porting Step 26: RBC-II Model + OBC Shock Filtering in SEP

Date: 2025-01-05

## Goal
Add the RBC-II model with the investment floor complementarity and ensure SEP integration **excludes OBC shocks** from the stochastic dimensions.

## What changed

### 1. Added RBC-II model
**File:** `models/RBCII_Dynare.jl`

- Ported Dynare `rbcii.mod` to MacroModelling.
- Added complementarity via:
  - `min(LagrangeMultiplier[0], Investment[0] - ZLB * Investment[ss]) = 0`
- Uses `ZLB = 0.85` and relies on the steady-state solver for `Investment[ss]`.

### 2. SEP solver: exclude OBC shocks from stochastic integration
**File:** `src/sep_solver.jl`

Problem:
- OBC shocks are auto-generated by MacroModelling and appear in `𝓂.exo`.
- SEP previously treated **all shocks** as stochastic, inflating `dε` and the GH nodes.

Fix:
- Identify OBC shocks by name (`"ᵒᵇᶜ"` in `𝓂.exo`).
- Use **only non-OBC shocks** as stochastic dimensions (`dε`).
- Build GH nodes/weights only for these shocks.
- Embed GH nodes into a **full exogenous vector** when evaluating residuals:
  - Deterministic shocks fill the full vector
  - GH nodes override only stochastic shock indices

Result:
- RBC-II SEP now uses `dε = 1` (just `epsilon`), not 42.

### 3. SEP IRF tree extraction: shock index mapping
**File:** `src/sep_irf.jl`

- `get_sep_irf_tree` now maps the requested shock index into the **stochastic shock index** used by SEP trees.
- Errors if the shock is OBC-only.

## Quick checks (local)
- `get_steady_state(RBCII_Dynare)` returns `Investment[ss] ≈ 0.241741953339343`.
- `solve!(RBCII_Dynare, algorithm=:stochastic_extended_path, sep_periods=5, sep_order=1, sep_nnodes=3)` converges with `layout.dε=1`.

## Notes
- SEP still warns about missing `z_<shock>` for `epsilon` (expected, since RBC-II uses `sigma` directly in the equation).
- If you want to suppress that warning, we can gate it behind `opts.verbose` or add a `shock_scaling` flag in SEP solver as a follow-up.
